rfnm_qec in decimated RX sessions (branch qec-decimated, 2026-11-20)
====================================================================

What changed
------------
Stock rfnm_qec only samples the native 122.88 MSps ring (qec_poll bails out unless
rfnm_stream_is_native_rx() and rfnm_local_rx_fmt == PACKED12). On-board apps (lorad,
adsld at 2 MSps = DCS 128 MHz, dcs1, k=5) therefore got neither the analog DC null nor
eps/phi estimation. The corrector itself already ran: the VSPA (apm-stock.eld) applies
iq_comp_params2_rx_dec @DMEM 0x2580 to the decimated ring (bench-proven on RFNM Blue
.124 at dcs0 k1-3 and dcs1 k3-6; 0x2600 has no effect there).

This branch adds, only in kernel_driver/la9310rfnm/rfnm_qec_main.c:
  - qec_dec_mode(): decodes the stream word via the exported rfnm_la9310_get_clock_state;
    rejects any TX share, k=0 and depths outside the rfnm_lalib RX ladder.
  - qec_dec_slot(): parser for decimated slots (variable subs, descriptors read once,
    epoch/DISCONT subs skipped, lags inside a sub only). The ring is raw packed12 VSPA
    output in every session, so the decimated path does not check rfnm_local_rx_fmt.
  - Module params (all 0644, change at runtime under /sys/module/rfnm_qec/parameters/):
      dec_enable=1    sample decimated rings (0 = stock behaviour)
      dec_dc_null=1   run the analog DCOFF null in decimated sessions, starting from the
                      live rfic_dc_i/q codes
      dec_iq=0        eps/phi model for rx_dec (seed-relative clamp, divergence latch).
                      Keep 0 until the on-board sign test (below) passed.
      dec_max_q20=52429, dec_step_q20=8192   dec_iq clamp / step
  With dec_iq=0 no DMA write happens in a decimated session (read-only + analog trim).

Measured on .124 (2026-11-20, 2 MSps, gain 30, LPF 4 MHz): DC -24..-26 dBFS -> -37..-53
dBFS; image rejection 34-36 -> 37-39 dB; lorad no regression.

dec_iq estimator (branch qec-dec-iq, 2026-11-21)
-----------------------------------------------
The 2026-11-20 lag regression (eps/phi/tau over lags 0..3) failed on real 2 MSps data:
phi 0.4-0.9 rad against a measured residual rho ~0.03. Cause (host port of the kernel code on
the recorded captures): a slow, linearly polarized component (DC wander / LO leakage, below
~20 kHz) makes rc(m) and ic(m) flat over all lags and dominates every moment.
Decimated windows now estimate from the first difference x(n)-x(n-1) (lag 0 minus lag 1),
tau pinned to the full-rate model:
    eps = (rc0 - rc1) / (ra0 - ra1),   phi = (ic0 - ic1) / (ra0 - ra1)
(a filter applied to both rails leaves eps/phi unchanged; the difference cancels the slow part).
Held when ra0 - ra1 < ra0/16 (no power off DC). Offline, integer port on 41 real captures:
1-8 MSps (dcs1 k3-k6, 29 captures): phi 29/29 and eps 28/29 within 20 % (or 0.003) of the
qec_ab.py g/rho, and the 0x2580 +0.05/+0.05 injection reads as -0.046..-0.051 on both (right
sign for the integrator). 15-61 MSps (dcs0): 8 of 12 off (ambient bursts rule the window
means), so dcs0 depths stay telemetry-only.
Also: dec_iq writes nothing to 0x2580 before its first accepted update (rx_dec keeps the
full-rate model till then); the decimated model is reseeded (learned offset kept) when the
full-rate model moved since its seed; the divergence latch needs |est| > 4e-3 and a growth by
more than 4e-3 per solve (window noise ~1.5e-3 tripped the old 1e-3 latch in a correct loop).
Host tests: notes rfnm-qec-open-2026-11-21/a1 (t3 = estimator on captures, t4 = closed loop
with simulated rx_dec, correct and flipped sign).

On-board sign test (not run yet; RX only, radio released, debug build = this branch +
rfnm-qec-dec-2026-11-20/debug/rfnm_qec_dbg.patch, dec_iq=0, verbose=1):
  1. 2 MSps session (rfnmiq 869.368 MHz gain 30 sma_a agc 0, ~60 s): >= 4 'est(uQ20)' lines -> E_off
  2. dbg_dcre_q20=0 dbg_dcim_q20=0 dbg_target=0 dbg_mode=1 (0x2580 := eps +0.05 phi +0.05) -> E_on
  3. dbg_mode=0 -> E_off2
  PASS: E_on - E_off = -(0.05 - seed) on both, i.e. about -0.05 after a reboot (offline on the
  2026-11-20 injection captures: -0.046..-0.051). Positive delta = flipped chain: leave dec_iq 0.
  4. After PASS, candidate module, dec_iq=1 in a lorad session: 'dec model' converges to E_off
  in ~10 solves, no 'diverging'; cs16 capture after: |rho| < 0.005, IRR_coh rises.

Build (host, matches the deployed vermagic 6.6.36-rt35-ga13146252326)
-----------------------------------------------------------------------
  Kernel tree rfnm/imx8mp-kernel a131462, Module.symvers of la9310shiva + la9310rfnm
  from a564201, aarch64-linux-gnu-gcc 14.2.0 (Debian 13 container):
    make -C <ksrc> ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- \
      M=<repo>/kernel_driver/la9310rfnm KBUILD_EXTRA_SYMBOLS=<extra.symvers> ... modules
  Only rfnm_qec.ko is needed; the core la9310rfnm.ko is unchanged.
  New undefined symbols vs stock: rfnm_la9310_get_clock_state, rfnm_tx_slot_rate_hz
  (both exported by the stock core module).

Deploy (no core reload, radio must be free)
-------------------------------------------
  curl -X POST -H 'Content-Type: application/json' -d '{"owner":"none"}' localhost/api/v1/radio
  cp /rfnm/kernel/rfnm_qec.ko /rfnm/kernel/rfnm_qec.ko.stock    # keep stock once
  rmmod rfnm_qec
  cp rfnm_qec.ko /rfnm/kernel/rfnm_qec.ko && insmod /rfnm/kernel/rfnm_qec.ko
  dmesg | grep rfnm_qec      # expect 'ring mode none -> dec dcs1 k5' on the next session
  Defaults are compiled in: load_drivers uses plain insmod, which ignores modprobe.d.

Rollback
--------
  Runtime:  echo 0 > /sys/module/rfnm_qec/parameters/dec_dc_null   (or dec_enable)
  Module:   release lease; rmmod rfnm_qec;
            cp /rfnm/kernel/rfnm_qec.ko.stock /rfnm/kernel/rfnm_qec.ko;
            insmod /rfnm/kernel/rfnm_qec.ko
